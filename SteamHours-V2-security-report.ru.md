## Краткий вывод

В опубликованном Python-файле не обнаружены явные функции кражи паролей, токенов, файлов, майнинга, шифрования данных или загрузки дополнительного исполняемого кода. Его видимая логика соответствует заявленной функции: чтение и изменение Steam `localconfig.vdf`, остановка Steam, отключение сетевых интерфейсов и повторный запуск Steam.

Однако **безопасность EXE не подтверждена**. Репозиторий не содержит исходного кода приложения, инструкции/конфигурации сборки, CI-сборки, attestation или воспроизводимой связи между `.py` и `.exe`. Оба файла вручную загружены как независимые release assets. Следовательно, аудит `.py` **не доказывает**, что EXE собран именно из него и не содержит дополнительного кода.

Кроме того, программа требует права администратора и выполняет потенциально разрушительные системные операции. Даже если это не вирус, ошибка или подмена бинарника получает высокий уровень воздействия.

## Что делает опубликованный Python-код

### Системные действия

- немедленно запрашивает повышение прав через Windows UAC (`runas`);
- ищет установку Steam и локальные Steam-профили;
- читает `loginusers.vdf` и `userdata/<id>/config/localconfig.vdf`;
- извлекает локальные имена аккаунтов, Steam ID, AppID и время игр;
- создаёт резервную копию `localconfig.vdf.backup` только при первом изменении;
- меняет `Playtime`/`Playtime2wks` в `localconfig.vdf`;
- делает `localconfig.vdf` read-only и временно снимает этот атрибут;
- принудительно завершает `steam.exe`, `steamwebhelper.exe`, `steamservice.exe`;
- через `netsh` отключает/включает интерфейсы Ethernet, Wi-Fi и «Беспроводная сеть»;
- запускает `steam.exe`;
- хранит конфигурацию и кэш в `%APPDATA%\SteamHoursChanger`.

### Сетевые обращения, видимые в коде

- `https://steamdb.info/app/<AppID>/`
- `https://store.steampowered.com/api/appdetails?...`
- `https://store.steampowered.com/app/<AppID>/`
- ссылки, открываемые по кнопкам: `discord.gg/cs-news`, `github.com/rodekplay`, `dalink.to/rodekplay1`.

В просмотренном `.py` не найдено отправки содержимого `loginusers.vdf`, `localconfig.vdf`, Steam ID или локальных файлов третьей стороне. Запросы за названиями игр раскрывают соответствующим серверам AppID, User-Agent и обычные сетевые метаданные (IP и т. п.).

## Опасные и подозрительные признаки

### Высокий риск воздействия

1. **Обязательные права администратора.** Для редактирования пользовательского VDF они выглядят избыточными; повышение требуется главным образом для управления службами/интерфейсами. Любой скрытый код в EXE при этом тоже получает права администратора.
2. **Принудительное завершение процессов и службы Steam.** Возможны потеря несохранённых данных, повреждение состояния клиента или конфликт с обновлением.
3. **Отключение сетевых интерфейсов.** Код использует `shell=True` и команды `netsh`. Это может оставить компьютер без сети при сбое программы.
4. **Изменение и блокировка `localconfig.vdf`.** Ошибка регулярного выражения, кодировки, конкурентная запись Steam или аварийное завершение могут повредить конфигурацию либо оставить файл read-only.
5. **Запуск `steam.exe` с `shell=True`.** Для фиксированного найденного пути прямой запуск без shell был бы безопаснее.

### Риски цепочки поставки

- в ветке `main` находится только `README.md`;
- история репозитория фактически состоит из одного коммита README;
- нет исходников в репозитории, build script, lock-файла зависимостей и CI;
- нет подписи издателя или опубликованной проверки Authenticode;
- нет GitHub artifact attestation/provenance;
- `.py` и `.exe` загружены отдельно, эквивалентность не доказана;
- аккаунт автора создан 25 июня 2026 г., репозиторий — 8 августа 2026 г.; у репозитория 1 звезда и 0 форков на момент проверки;
- открытый issue №1 прямо указывает на отсутствие исходников и проверяемой сборки.

Малое число загрузок, звёзд или молодой аккаунт сами по себе не доказывают вредоносность, но означают недостаток репутационных сигналов.

## Что не обнаружено в опубликованном `.py`

При ручном статическом просмотре не обнаружены:

- чтение браузерных профилей, cookies или менеджеров паролей;
- поиск Steam `ssfn`, session/token-файлов с последующей отправкой;
- Discord webhook, Telegram Bot API или иной код эксфильтрации;
- скачивание и запуск payload;
- PowerShell, WMI, планировщик задач, Run-ключи или иная персистентность;
- кейлоггер, захват экрана/буфера обмена;
- криптомайнинг;
- шифрование пользовательских файлов или ransomware-логика;
- отключение Defender/антивируса;
- обфускация, `eval`/`exec`, Base64-пayload в представленном исходнике.

Это относится **только к опубликованному `.py`**, а не к EXE.

## Ограничения проверки

В ходе этой проверки не удалось надёжно получить байты EXE из GitHub CDN из-за повторяющегося TLS/EOF-сбоя окружения. Поэтому не выполнены:

- локальное подтверждение SHA-256;
- проверка Authenticode и цепочки сертификата;
- анализ PE-заголовков, импортов, секций, entropy и packer-признаков;
- извлечение PyInstaller-архива и сравнение bytecode с `.py`;
- сканирование локальными ClamAV/YARA/Defender;
- отправка/поиск файла в VirusTotal, MetaDefender, Hybrid Analysis и ANY.RUN;
- динамический анализ процессов, файловой системы, реестра и сети в Windows sandbox.

Публичный веб-поиск по SHA-256 EXE не дал достоверной карточки или результатов мультисканера. Отсутствие результата **не означает**, что файл чистый.

## Рекомендации пользователю

1. **Не запускать EXE на основной Windows.** Особенно если на компьютере есть криптокошельки, сохранённые пароли, рабочие документы или ценный Steam-аккаунт.
2. Если тест абсолютно необходим — использовать одноразовую Windows VM без общих папок, буфера обмена, проброса дисков и сохранённых аккаунтов; сделать snapshot до запуска.
3. Не входить в основной Steam-аккаунт; использовать отдельный тестовый аккаунт без средств и ценных предметов.
4. До запуска проверить точный SHA-256 и не продолжать, если он отличается от GitHub digest.
5. Проверить файл минимум через Microsoft Defender и несколько независимых движков. Не считать 0 детектов абсолютной гарантией.
6. Проверить цифровую подпись в свойствах файла или `Get-AuthenticodeSignature`; отсутствие/невалидность подписи считать дополнительным риском.
7. Предпочесть просмотренный `.py` в изолированной среде вместо непрозрачного EXE, но только после самостоятельной проверки зависимостей и удаления ненужного повышения прав/`shell=True`.
8. Сделать отдельную копию `localconfig.vdf` вне каталога Steam и убедиться, что сеть можно вернуть вручную.
9. Лучшее исправление со стороны автора: полный исходный код в Git, pinned dependencies, CI-сборка GitHub Actions, artifact attestation, воспроизводимая инструкция и подписанный релиз.

Из-за непрозрачной сборки, обязательных прав администратора и опасных системных операций запуск `SteamHours-V2.exe` следует считать неоправданно рискованным. Моя рекомендация — не запускать этот EXE на реальной системе.**
